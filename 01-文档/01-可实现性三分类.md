## 四、规格书本身的缺口（我的独立清单）

| 编号 | 类型 | 内容 |
|---|---|---|
| G-1 | **结构性缺口（最重要）** | **59 条里没有任何一条定义"MC Java 启动底座"**。JRE 运行时来源、图形翻译层、音频、输入注入、进程隔离全部缺位，而整栋楼都建在它上面。这不是措辞问题，是整个项目最大的单点风险，且工作量大于其余所有条目之和 |

| G-4 | 技术陈述可能过时 | 2.3 节 `os.chmod(0o755)` + `System.load` 兜底在 Android 10+ 的 W^X/SELinux 限制下大概率不成立。模块 native 库应走 `ApplicationInfo.nativeLibraryDir` 合法路径（宿主 APK 的 jniLibs，或独立安装的 APK 的 native 目录） |
| G-5 | 验收样本缺失 | 第 28 条"与参考实现逐字一致"未指名参考实现；第 34 条"与参考实现一致"未给种子清单 |
| G-6 | 未覆盖 | 第 30 条按特征解析 FCL 私有格式属逆向，版权/许可口径未覆盖。需补"参考项目许可核实清单"为强制前置 |
| G-7 | **范围缺口（副审提出，我采纳）** | 第 33 条"正版上传"需要 Microsoft OAuth → Xbox Live → XSTS → Minecraft Services 整条认证链，但**规格书通篇没有账号登录条目**——没有任何一条定义登录态、token 存储与续期、多账号、登出。这不是工程难度问题，是范围缺口：要么承认第 33 条需要新增一个未在 59 条里出现的"账号体系"，要么砍掉正版上传只保留本地皮肤编辑。必须由用户裁决 |
| G-8 | 未覆盖 | 第 8 条地区闸需要 `READ_PHONE_STATE` 运行时权限（`getSimCountryIso` / `getNetworkCountryIso`），而规格书没有定义：谁在什么时机请求、用户拒绝是否等同于"信号失败"、拒绝后是否仍显示入口。拒绝→默认大陆在合规上最保守，但"启动器一上来要电话权限"的体验与上架审核风险无人评估。属已锁条目 8/25 落地的第一道坎 |
